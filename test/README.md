# ساختار و اجرای تست‌ها

تست در پایین‌ترین لایهٔ مؤثر نگهداری می‌شود:

- <span dir="ltr">`unit/`</span>: محاسبه و رفتار دامنه.
- <span dir="ltr">`repository/`</span>: <span dir="ltr">SQLite</span>، قید، تراکنش، مهاجرت، بازگشایی و دوام.
- <span dir="ltr">`scenario/`</span>: سناریوهای ترکیبی دامنه.
- <span dir="ltr">`widget/`</span>: مسیر کاربر، تازه‌سازی و حالت‌های رابط.
- <span dir="ltr">`integration/`</span>: اتصال برنامه و پلتفرم؛ جایگزین شاهد دستگاه نیست.
- <span dir="ltr">`fixtures/`</span>: دادهٔ آزمون و نمونهٔ نسخه‌دار.

از ریشهٔ مخزن:

<div dir="ltr">

```sh
flutter test
flutter analyze
```

</div>

شرایط بررسی مشترک و امضای <span dir="ltr">Android</span> در [گردش توسعه](../docs/development-workflow.md) آمده است. نتایج خام محلی در <span dir="ltr">`build/verification/`</span> و خلاصهٔ شاهد در سند همان قابلیت ثبت می‌شوند. تعداد تست قدیمی نتیجهٔ اجرای جدید نیست.

تست دامنه محاسبه را ثابت می‌کند؛ دوام به پایگاه دادهٔ تولیدی و بازگشایی، مسیر کاربر به تست رابط و رفتار بومی به بررسی دستگاه نیاز دارد. برای نقص مهم، سناریوی شکست و معیار پذیرش را پیش از اصلاح ثبت کنید.

</div>
