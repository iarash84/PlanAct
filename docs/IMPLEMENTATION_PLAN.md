# نقشهٔ توسعهٔ مرحله‌ای

این سند ترتیب مفهومی مراحل را نگه می‌دارد، نه فهرست پرامپت قابل اجرا یا اعلام تکمیل قابلیت‌ها. ارجاع <span dir="ltr">P00</span> تا <span dir="ltr">P38</span> به پوشهٔ ناموجود <span dir="ltr">`prompts/`</span> حذف شده است. وضعیت واقعی از [<span dir="ltr">PRD</span>](product/PRD.md) و گزارش پذیرش همان قابلیت خوانده می‌شود.

## روش کار

دامنهٔ محدود، مسیر واقعی، قرارداد پذیرش و تست مرتبط را پیش از تغییر تعیین کنید. هر تغییر مستقل، بازبینی و ثبت جدا داشته باشد؛ مهاجرت و تست آن همراه همان تغییر باشند. تصمیم معماریِ تازه در <span dir="ltr">ADR</span> ثبت شود. [گردش توسعه](development-workflow.md) مرجع اجرای جاری و [<span dir="ltr">AGENTS</span>](../AGENTS.md) قرارداد عامل است.

## تصمیم‌های موجود

انتخاب شناسهٔ <span dir="ltr">UUIDv7</span>، <span dir="ltr">SQLite/Drift</span>، کتابخانه‌های رمزنگاری و آداپتور یادآور در کد و [<span dir="ltr">ADR</span>ها](adr/) ثبت شده‌اند؛ عبارت قدیمی «هنوز انتخاب نشده» برای این موارد معتبر نیست. انتخاب تازهٔ مدیریت وضعیت، قالب داده، رمزنگاری پایگاه داده یا رفتار چندارزی نباید بی‌صدا انجام شود.

تکمیل یک مرحلهٔ زیرساختی به معنی آماده‌بودن همهٔ مسیرهای کاربر نیست. آزمون ناموفق یا اجرا‌نشدهٔ لازم، اجازهٔ اعلام آمادگی انتشار نمی‌دهد.
