# PlanAct 0.1.15 release candidate

## Acceptance contract (2026-10-13)

- Entry: the sole maintainer dispatches Release Android on master with version 0.1.15. Repository-level production signing and symbol-encryption secrets are prerequisites; no GitHub Environment or second reviewer is required (maintainer-approved change, 2026-10-13).
- Outcome: build a candidate from the dispatch's immutable commit, run shared validation and APK verification, retain APKs/checksums plus source/build identity, then automatically publish those exact files after successful validation. No rebuild during publication and no claim of independent acceptance.
- Failure/cancellation: failed build/validation or artifact identity/checksum mismatch prevents publication. Cancellation before publication prevents release creation; cancellation after the GitHub create request may leave a release and must be checked before retry. Existing versions are never overwritten. Start a new run after corrections.
- Scope: version/release metadata and release automation only. No domain, schema, migration, dependency, backup-format or visual changes. Installed app version continues to come from platform package metadata.
- Evidence required: local lockfile/format/analyze/tests; CI signed universal/split APK verification; independent review attached to commit, run number and SHA256SUMS; real-device upgrade, backup/restore, permissions, app lock and reminder checks. CI success is not product acceptance.

## Changes since 0.1.14

- Long-term hybrid commitments: bounded future previews and explicit transactional occurrence preparation, preserving count/end-date semantics and history.
- Candidate/publication separation, immutable source revision and verified-artifact reuse; automatic publication for solo maintenance.
- Application version 0.1.15+8. Published Android versionCode remains the release workflow run number; verify it exceeds every previously distributed APK, including local builds.

## Release blockers / ownership

Owner: release maintainer. The explicit solo-maintainer decision removes the GitHub Environment/reviewer deployment gate only. Keep secrets at repository scope, retain artifact checksums and record verification against the exact commit/run. Manual dispatch authorizes automatic publication after technical checks; it does not establish independent product acceptance. The environment assertions and approval checks reported above are historical evidence for the superseded workflow.

Required inherited gates remain open unless separately evidenced in their existing verification records: isolated fresh-install recovery-key backup/restore and in-flight command exclusion; app-lock authentication/lifecycle/recents privacy; native notification delivery/reboot/permissions; SMS provider/privacy and account clipboard/privacy; recurrence/hybrid device journeys and older-writer semantic compatibility.
