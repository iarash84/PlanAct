# PlanAct 0.1.15 release candidate

## Acceptance contract (2026-10-13)

- Entry: maintainer dispatches Release Android on master with version 0.1.15. Production signing secrets and a preconfigured android-release environment with required independent reviewers are prerequisites.
- Outcome: build a candidate from the dispatch's immutable commit, run shared validation and APK verification, retain candidate APKs/checksums plus source/build identity for device acceptance, then publish those exact files only after environment approval. No rebuild during publication.
- Failure/cancellation: validation or missing review configuration prevents publication; rejected/cancelled approval leaves no public tag/release. Existing versions are never overwritten. Start a new run after corrections; review the new candidate again.
- Scope: version/release metadata and release automation only. No domain, schema, migration, dependency, backup-format or visual changes. Installed app version continues to come from platform package metadata.
- Evidence required: local lockfile/format/analyze/tests; CI signed universal/split APK verification; independent review attached to commit, run number and SHA256SUMS; real-device upgrade, backup/restore, permissions, app lock and reminder checks. CI success is not product acceptance.

## Changes since 0.1.14

- Long-term hybrid commitments: bounded future previews and explicit transactional occurrence preparation, preserving count/end-date semantics and history.
- Candidate/publication separation, immutable source revision and reviewed-artifact reuse.
- Application version 0.1.15+8. Published Android versionCode remains the release workflow run number; verify it exceeds every previously distributed APK, including local builds.
