# PlanAct 0.1.16 release candidate

## Acceptance contract (2026-10-14)

- Entry: the maintainer explicitly dispatches Release Android on master with version 0.1.16 after reviewing acceptance evidence. Repository-level production signing and symbol-encryption secrets are prerequisites. This preparation does not authorize dispatch, commit, push, tag creation or publication.
- Outcome: version 0.1.16+9, target tag v0.1.16 and release documentation agree. The existing workflow validates the immutable dispatch commit, signs/verifies the APKs and publishes the exact candidate without rebuilding. The version-specific release record travels with that candidate and supplies the GitHub release body.
- Failure/cancellation/retry: missing or mismatched release notes, failed technical validation or artifact identity/checksum mismatch prevents publication. Existing tags/releases are not overwritten. Cancellation after the create request may leave a release; inspect GitHub before retrying. Corrections require a new run.
- Scope: release metadata, notes and their automation wiring only; no domain behavior, schema, migration, dependency, backup-format or visual changes in this preparation. Installed app version continues to use platform package metadata.
- Evidence: local lockfile-enforced resolution, generated-copy/format checks, analysis and full tests; workflow structure and Bash syntax; release-record links and diff checks. Production-signed APK verification, remote Actions/API execution, real-device journeys and independent acceptance must be recorded separately against the final commit/run/checksums. Successful CI is not release readiness.

## Changes since 0.1.15

Grounded in local Git history from v0.1.15 through e6d8aae; these are implementation changes, not independently accepted release capabilities:

- Commitment creation now uses one form with expandable optional sections and an editable live summary, retaining explicit scheduling choices and retry state.
- Personal reports and financial charts: Jalali date/tag filters, recorded-versus-preview separation, cash comparisons, category shares, daily ledger balances and settlement views.
- More compact Calendar Month layout and focused visual consistency improvements without changing scheduling semantics.
- Inbox monetary displays and inputs use grouped exact amounts; ambiguous SMS units visibly suggest the app preference but require explicit saving. Confirmed transactions support optional tags.
- Bank logos appear in account cards and account pickers using local assets.
- About provides Persian product/privacy/permission/backup guidance, installed version with retry, and offline license/dependency notices.
- Persian application copy is centralized in generated localization resources and pure-Dart defaults. Persian remains the only enabled language; this is localization foundation, not multilingual readiness.
- Device-gallery documentation and opt-in synthetic seed tooling were added; gallery images are not evidence of acceptance for the final release APK.
- Five monetary-input/SMS review test expectations were corrected to match approved grouping and explicit-unit behavior, with cancellation and failed-save retention coverage; no app behavior was changed by that test-only fix.
- This preparation selects 0.1.16+9 and wires version-specific notes into the existing verified-candidate publication path. Published Android versionCode remains the Release Android workflow run number, not the local suffix 9; it must exceed every previously distributed APK's code.
