# تصمیم معماری ۰۰۰۳: وابستگی و حریم خصوصی پایه

وضعیت: پذیرفته‌شده؛ تاریخ: <span dir="ltr">۲۰۲۶-۰۹-۲۰</span>.

ابزار تست و تحلیل موجود <span dir="ltr">Flutter</span> و <span dir="ltr">SQLite/Drift</span> استفاده می‌شوند. کد جدول با <span dir="ltr">`build_runner`</span> و <span dir="ltr">`drift_dev`</span> تولید می‌شود. وابستگی تازهٔ مدیریت وضعیت، اعلان، رمزنگاری یا ثبت گزارش باید به نیاز معماری مشخص و تصمیم همان مرحله وابسته باشد.

ثبت گزارش محلی، دادهٔ حساس را در سطح فیلد می‌پوشاند. متن خام پیامک، یادداشت خصوصی، شناسهٔ حساب، مبلغ حساس، توکن و راز به‌طور پیش‌فرض ثبت نمی‌شوند. هسته آفلاین است و وابستگی ارسال دورسنجی افزوده نمی‌شود. آداپتور بومی آینده می‌تواند خروجی کنترل‌شده فراهم کند، بدون وابسته‌کردن دامنه به پلتفرم.

این تصمیم تاریخی مانع استفاده از وابستگی‌های بعداً مصوبِ موجود در <span dir="ltr">`pubspec.yaml`</span> نیست؛ نسخه و توجیه آن‌ها از تصمیم مربوط و فایل قفل خوانده می‌شود.
