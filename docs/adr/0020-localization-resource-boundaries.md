# تصمیم معماری ۰۰۲۰: منابع ترجمه و مرز سازگاری

تاریخ: <span dir="ltr">۲۰۲۶-۱۰-۱۴</span>؛ وضعیت: پذیرفته‌شده برای زیرساخت فقط فارسی.

از <span dir="ltr">`gen-l10n`</span> داخلی <span dir="ltr">Flutter</span>، <span dir="ltr">ARB</span> فارسی در <span dir="ltr">`lib/l10n`</span>، <span dir="ltr">`AppLocalizations`</span> تولیدشده و منابع چارچوب استفاده می‌شود. تنها زبان/منطقه فعال فارسی است؛ راست‌به‌چپ، جلالی و پول صحیح حفظ می‌شوند. <span dir="ltr">`intl`</span> با نسخهٔ از پیش تعیین‌شدهٔ <span dir="ltr">`0.20.3`</span> مستقیم اعلام شد؛ نسخهٔ بسته یا مدیریت وضعیت تازه اضافه نشد.

دامنه رابط برنامه‌نویسی ترجمهٔ <span dir="ltr">Flutter</span> را وارد نمی‌کند. مولد کوچکِ مستقل <span dir="ltr">Dart</span>، متن دارای <span dir="ltr">`x-planact-default`</span> را به <span dir="ltr">`PersianCopy`</span> تبدیل می‌کند تا <span dir="ltr">API</span> رشته‌ای/ثابت قدیمی، متن دقیق و مصرف تاریخی/بومی حفظ شود. خروجی تولیدی منبع دستی دوم نیست و بازتولیدپذیری در بررسی مشترک کنترل می‌شود. توابع نمایشی بدون بافت همین مرز صریح را دارند؛ زبان بعدی باید ورودی ترجمه یا نگاشت نوع‌دار را از این مرز عبور دهد.

واژگان تجزیه، بانک/تعطیلات، یادداشت/دستهٔ ماندگار، هویت ارز و نرمال‌سازی عدد منبع ترجمه نیستند. دادهٔ کاربر و منبع بازنویسی نمی‌شود. فعال‌سازی زبان مجوز تغییر تقویم تکرار، لنگر، واحد ذخیره یا تصمیم تاریخی نیست.

این تغییر بدون مهاجرت یا ترجیح زبان تازه، متن برنامه را متمرکز می‌کند؛ خروجی سازگاری همچنان فارسی است. پیش از زبان دیگر، مسیر، جهت، قالب، محاسبه/خطا/تابع بدون بافت و متن بومی اعلان/احراز هویت باید بررسی شوند. [شواهد ترجمه](../LOCALIZATION_VERIFICATION.md)
