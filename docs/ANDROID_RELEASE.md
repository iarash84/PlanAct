# ساخت و انتشار Android

## امضا

همهٔ ساخت عمومی باید یک مخزن کلید انتشارِ پایدار داشته باشند. کلید و `android/key.properties` در Git قرار نگیرند و پشتیبان امن آفلاین داشته باشند؛ تغییر/گم‌شدن کلید می‌تواند به‌روزرسانی نصب موجود را ناممکن کند.

رازهای سطح مخزن GitHub Actions:
- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`
- `ANDROID_SIGNING_CERT_SHA256`: اثرانگشت گواهیِ مورد انتظار؛ گواهی متفاوت رد می‌شود.
- `SYMBOLS_ENCRYPTION_PASSPHRASE`: راز قویِ رمزگذاری نمادهای مبهم‌سازی؛ نماد عمومی منتشر نمی‌شود.

راز فقط در محیط انتشار، جای راز سطح مخزن این گردش‌کار را نمی‌گیرد. پیکربندی محلی:

```properties
storeFile=C:/secure/keys/planact-release.jks
storePassword=...
keyAlias=planact-release
keyPassword=...
```

مسیر مطلق یا نسبت به `android/` است. مخزن کلید و نام مستعار محلی/انتشار یکسان باشند. Gradle با امضای ناقص شکست می‌خورد و به کلید آزمایشی برنمی‌گردد.

```sh
keytool -list -v -keystore path/to/planact-release.jks -alias planact-release
```

## انتشار نسخه

نسخهٔ `X.Y.Z+N` را در `pubspec.yaml` و یادداشت `docs/releases/X.Y.Z.md` ثبت و روی `master` آماده کنید. از `Actions → Release Android → Run workflow` همان شاخه و `X.Y.Z` بدون `v` یا `+N` را انتخاب کنید. برچسب را قبلاً نسازید؛ گردش‌کار برچسب/انتشار موجود را رد و فقط بعد از اعتبارسنجی و امضای APK، `vX.Y.Z` را روی ثبت گیت دقیق می‌سازد. ارسال برچسب به‌تنهایی آغازگر نیست.

هدف جاری `0.1.16+9` و ورودی انتشار `0.1.16` است. [موانع پذیرش](releases/0.1.16.md) مستقل‌اند؛ آماده‌سازی مستند مجوز آغاز دستی نیست. یادداشت خالی، نامزد نامنطبق یا هش کنترلی تغییرکرده رد می‌شود و متن یادداشت با هویت ساخت بدنهٔ انتشار را می‌سازد.

سیاست مصوب ۲۰۲۶-۱۰-۱۳ برای نگهدارندهٔ فردی، GitHub محیط انتشار، بازبین دوم اجباری یا تأیید استقرار نمی‌خواهد. آغاز دستی پس از بررسی فنی اجازهٔ انتشار خودکار می‌دهد؛ مسئولیت بررسی محصول/دستگاه همچنان با نگهدارنده است.

ساخت از ثبت گیت تغییرناپذیر آغاز دستی انجام می‌شود. نامزد `PlanAct-vX.Y.Z-candidate-RUN_ID` سی روز نگهداری و همان فایل بدون ساخت دوباره منتشر می‌شود. هویت و هش کنترلی کنترل می‌شوند؛ شکست بررسی مانع انتشار است و لغو پس از ایجاد انتشار آن را واگرد نمی‌کند. ثبت گیت تازه اجرای تازه می‌خواهد.

`versionName` باید با نسخهٔ درخواست‌شده/فایل پروژه برابر باشد. ساخت محلی از پسوند پروژه استفاده می‌کند، ولی APK منتشرشده `github.run_number` را `versionCode` می‌گیرد. اجرای دوبارهٔ همان اجرا شماره را زیاد نمی‌کند؛ اجرا تازه زیاد می‌کند. شماره باید از هر APK قبلاً توزیع‌شده بیشتر باشد؛ پسوند محلی اثبات این ترتیب نیست. همهٔ APKهای یک اجرا شمارهٔ برابر دارند.

Flutter `3.47.5` و Dart `3.13.4` در گردش‌کارها تثبیت شده‌اند. بررسی مشترک فایل قفل، قالب، تحلیل، تست و App Bundle را می‌سنجد. CI کلید موقت و انتشار کلید تولیدی دارد. R8/کوچک‌سازی منابع و مبهم‌سازی Dart برای APK انتشار فعال‌اند؛ نمادهای جامع/تفکیک‌شده در مسیر جدا رمزگذاری و نود روز به‌عنوان خروجی خصوصی Actions نگهداری می‌شوند.

## فایل‌ها و بررسی

- `PlanAct-vX.Y.Z-universal.apk`: برای اغلب دستگاه‌ها.
- `arm64-v8a`: گوشی ARM جدید؛ `armeabi-v7a`: ARM سی‌ودوبیتی؛ `x86_64`: اغلب شبیه‌ساز.
- `SHA256SUMS.txt`، `SIGNING-CERTIFICATE-SHA256.txt` و `BUILD-IDENTITY.txt`: سلامت، امضا و منشأ ساخت.

```sh
sha256sum -c SHA256SUMS.txt
adb install path/to/PlanAct-vX.Y.Z-universal.apk
```

`adb install -r` فقط برای ارتقای همان شناسه و امضاست. خطاها:
- `INSTALL_FAILED_NO_MATCHING_ABIS`: نسخهٔ جامع یا ABI مناسب.
- `INSTALL_FAILED_UPDATE_INCOMPATIBLE`: امضای متفاوت؛ داده را قبل از هر حذف نصب قابل بازیابی کنید.
- `INSTALL_FAILED_VERSION_DOWNGRADE`: شمارهٔ کمتر؛ ساخت جدیدتر لازم است.
- `INSTALL_FAILED_OLDER_SDK`: Android پایین‌تر از حداقل.
- `INSTALL_PARSE_FAILED_*`: فایل خراب/ناخوانا؛ دریافت مجدد و هش کنترلی.

شناسهٔ جاری `com.iarash.planact` نصب `com.example.planact` را ارتقا نمی‌دهد. کلید آزمایشی قدیمی هم هویت انتشار نیست. **نصب حاوی دادهٔ شخصی را صرفاً برای رفع خطای نصب حذف نکنید.** پشتیبان قالب ۱ با ازدست‌رفتن کلید نصب ممکن است بازیابی نشود. انتقال باید پس از تأیید بازیابی در نصب آزمایشی جدا، با فایل و کلید مستقلِ معتبر یا مسیر مهاجرتِ پذیرفته‌شده انجام شود.

خروجی کامل Package Manager را بدون دادهٔ حساس حفظ کنید. گردش‌کار ZIP، alignment، بسته/نسخه، حداقل SDK، ABI و گواهی غیرآزمایشی را بررسی می‌کند. برای رمزگشایی نماد، خروجی همان نسخه و رمز حفظ‌شده و پوشهٔ نماد همان ABI را به `flutter symbolize` بدهید. ساخت و اجرای جدید در این تنقیح مستند انجام نشده است.
