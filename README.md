<h1 align="center"><span dir="ltr">PlanAct</span></h1>

**<span dir="ltr">PlanAct</span>** یک دستیار شخصی برای مدیریت تعهدها، برنامه‌ها و امور مالی روزمره است؛ ابزاری که کمک می‌کند همیشه بدانید:

1. چه چیزی قرار بود اتفاق بیفتد؟
2. در عمل چه اتفاقی افتاد؟
3. اکنون چه چیزی نیاز به توجه دارد؟

<span dir="ltr">PlanAct</span> صرفاً یک تقویم، فهرست کارها، اپلیکیشن یادآوری یا حسابداری نیست. این برنامه همه این قابلیت‌ها را در یک چرخه منسجم کنار هم قرار می‌دهد:

**برنامه‌ریزی → زمان‌بندی → یادآوری → اقدام → ثبت واقعیت → تطبیق → تکمیل**

## قابلیت‌های اصلی

### مدیریت تعهدها

- ثبت تعهدهای شخصی، خانوادگی، آموزشی، کاری و مالی
- نگهداری تعهد به‌عنوان یک مفهوم پایدار، مستقل از جلسات و رخدادهای آن
- پشتیبانی از چرخه‌های مختلف یک تعهد؛ برای مثال ترم‌های جداگانه کلاس یا بسته‌های متوالی خدمات
- وضعیت‌های روشن برای تعهدهای فعال، متوقف‌شده و بایگانی‌شده
- ثبت یادداشت، اولویت، نوع تعهد و برچسب‌ها
- حفظ تاریخچه هنگام تکمیل، لغو، توقف یا تغییر تعهد

### زمان‌بندی و تقویم

- برنامه‌های یک‌باره و تکرارشونده
- بازه زمانی ثابت، تعداد جلسات مشخص، بسته‌های دستی و برنامه‌های ترکیبی
- تولید محدود و قابل کنترل رخدادهای آینده، بدون ساختن بی‌نهایت رکورد
- ویرایش فقط یک رخداد، این رخداد و رخدادهای بعدی، یا چرخه فعال
- حفظ رخدادهای گذشته هنگام تغییر برنامه
- مدیریت تفاوت بین زمان محلی، لحظه ثابت و تاریخ تمام‌روز
- در نظر گرفتن تعطیلی، توقف موقت، تعارض زمانی، تغییر منطقه زمانی، سال کبیسه و روزهای انتهایی ماه
- نمایش تاریخ‌ها با تقویم جلالی و قالب‌بندی فارسی برای کاربر

### کلاس‌ها، جلسات و بسته‌های خدماتی

<span dir="ltr">PlanAct</span> برای تعهدهایی مثل کلاس زبان، موسیقی، شنا، جلسات مشاوره و بسته‌های خدماتی طراحی شده است:

- مدیریت تعداد جلسات یا واحدهای قابل استفاده
- تفکیک زمان‌بندی جلسه از اعتبار باقی‌مانده
- ثبت خرید، مصرف، بازگردانی، اصلاح، انقضا و استرداد اعتبار
- پشتیبانی از لغو توسط ارائه‌دهنده، غیبت مجاز، لغو دیرهنگام، عدم حضور و تعطیلی
- ساخت جلسه جبرانی و زنجیره جایگزینی بدون حذف سابقه
- پشتیبانی از توقف یا <span dir="ltr"><strong>Freeze</strong></span> و ادامه برنامه بر اساس سیاست مشخص
- جداسازی <span dir="ltr"><code>planned end date</code></span> از <span dir="ltr"><code>actual end date</code></span>
- محاسبه اعتبار باقی‌مانده از دفترکل، نه از یک شمارنده غیرقابل اعتماد

### یادآوری‌های قابل اتکا

- تعریف یادآوری نسبت به زمان رخداد
- ساخت نمونه واقعی یادآوری برای هر رخداد
- لغو و بازسازی یادآوری‌ها هنگام جابه‌جایی برنامه
- حذف یادآوری‌های غیرضروری پس از تکمیل، لغو یا رد شدن رخداد
- پشتیبانی از تعویق یادآوری بدون تغییر قانون اصلی
- بازسازی یادآوری‌های آینده پس از راه‌اندازی مجدد برنامه یا بازیابی نسخه پشتیبان
- جلوگیری از یادآوری‌های تکراری و بدون صاحب

### ثبت آنچه واقعاً اتفاق افتاده

- ثبت تکمیل، حضور، لغو، غیبت، عدم حضور، نتیجه و یادداشت
- تفکیک برنامه‌ریزی از واقعیت ثبت‌شده
- نگهداری تاریخچه قابل توضیح برای رخدادهای حل‌شده
- امکان اتصال رخدادها به شواهد و تراکنش‌های مرتبط در جریان‌های بعدی
- جلوگیری از حذف بی‌صدای سابقه هنگام اصلاح اطلاعات

### مدیریت مالی مبتنی بر دفترکل

- پشتیبانی از حساب بانکی، کیف پول نقدی و کیف پول دیجیتال
- ثبت درآمد، هزینه، انتقال، اصلاح، استرداد و برگشت تراکنش
- محاسبه موجودی از روی ورودی‌های حساب و امکان بازسازی آن
- ذخیره مبلغ به‌صورت عدد صحیح در واحد خرد، بدون خطای محاسبات اعشاری
- تشخیص انتقال بین حساب‌های خود کاربر به‌عنوان انتقال، نه درآمد یا هزینه
- بایگانی حساب‌های دارای سابقه به‌جای حذف آن‌ها

### تطبیق مالی با تعهدها

- اتصال تراکنش‌های مالی به رخدادها و تعهدها
- پشتیبانی از پرداخت کامل، پرداخت ناقص، چند پرداخت برای یک تعهد و پرداخت اضافه
- تطبیق چندبه‌چند با امکان اصلاح و حفظ تاریخچه
- نمایش اختلاف بین مبلغ برنامه‌ریزی‌شده و مبلغ واقعی
- عدم تغییر مخفیانه تطبیق‌ها و نیاز به تأیید کاربر برای تصمیم‌های مهم

### <span dir="ltr">Inbox</span> و ورود اطلاعات

- دریافت اطلاعات واردشده از منابع مختلف در یک مرحله موقت
- حفظ منبع و منشأ داده برای بررسی و بازگشت‌پذیری
- پردازش محلی پیامک‌ها و تبدیل آن‌ها به پیش‌نویس تراکنش
- تشخیص موارد تکراری پیش از ایجاد داده نهایی
- پیشنهاد تعهد، دسته‌بندی، پذیرنده یا تطبیق مالی
- تأیید، ویرایش یا رد پیشنهادها توسط کاربر
- جلوگیری از ورود مستقیم داده خام به دفترکل نهایی

### اتوماسیون و پیش‌بینی محلی

- نرمال‌سازی نام پذیرنده‌ها و شناسایی الگوهای پرداخت دوره‌ای
- پیشنهاد تطبیق بر اساس مبلغ، تاریخ و نام پذیرنده با دلایل قابل فهم
- پیشنهاد دسته‌بندی با الزام تأیید کاربر
- پیش‌بینی پرداخت‌های آینده بر اساس الگوهای قطعی و قابل توضیح
- شناسایی ریسک‌هایی مانند رخداد عقب‌افتاده، سررسید نزدیک، غیبت‌های اخیر یا کمبود موجودی
- شناسایی انحراف غیرعادی مبلغ نسبت به سابقه پرداخت‌ها
- امکان استفاده از پردازش اختیاری هوش مصنوعی روی دستگاه
- ادامه کامل قابلیت‌های اصلی در صورت خاموش بودن یا در دسترس نبودن هوش مصنوعی
- عدم انجام تغییر مخفیانه در تاریخچه، موجودی، اعتبار یا تطبیق‌های مالی

### پشتیبان‌گیری و بازیابی

- ساخت بسته پشتیبان همراه با نسخه طرحواره، نسخه برنامه، زمان ایجاد و <span dir="ltr"><code>checksum</code></span>
- اعتبارسنجی نسخه پشتیبان پیش از جایگزینی داده فعلی
- ساخت <span dir="ltr"><code>snapshot</code></span> ایمنی پیش از بازیابی
- حفظ داده فعلی در صورت نامعتبر بودن نسخه پشتیبان
- جایگزینی اتمیک داده‌ها و بازسازی محاسبات مشتق‌شده و یادآوری‌ها پس از بازیابی

### حریم خصوصی و استفاده آفلاین

- هسته اصلی برنامه به اینترنت، حساب ابری یا سرویس هوش مصنوعی ابری وابسته نیست
- داده‌های شخصی و مالی به‌صورت پیش‌فرض روی دستگاه باقی می‌مانند
- پردازش‌های اتوماسیون و پیش‌بینی بر پایه قواعد محلی و قابل توضیح انجام می‌شوند
- اطلاعات حساس در لاگ‌های عادی ثبت نمی‌شوند
- تصمیم‌های مهم مالی، تاریخی و مربوط به اعتبار نیازمند کنترل و تأیید کاربر هستند

## اصول تجربه محصول

با چند اصل، <span dir="ltr">PlanAct</span> ساخته می‌شود:

- **آفلاین‌محور:** قابلیت‌های اصلی بدون اینترنت کار می‌کنند.
- **حریم خصوصی‌محور:** داده‌های شخصی و مالی در اختیار کاربر باقی می‌مانند.
- **تاریخچه‌محور:** اصلاح یا تغییر نباید گذشته را پاک کند.
- **قابل توضیح:** پیشنهادها، امتیازها و پیش‌بینی‌ها دلیل مشخص دارند.
- **انسان در حلقه:** اتوماسیون پیشنهاد می‌دهد، اما تصمیم‌های حساس را کاربر تأیید می‌کند.
- **فارسی و راست‌به‌چپ:** تجربه کاربری برای زبان فارسی و تقویم جلالی طراحی شده است.
- **هسته قطعی:** محاسبات زمان، وضعیت، اعتبار، موجودی و تطبیق قابل تست و بازسازی هستند.

<span dir="ltr">PlanAct</span> در حال توسعه مرحله‌ای است و بخش‌های اصلی دامنه، زمان‌بندی، جلسات، یادآوری، ثبت واقعیت، مالی، تطبیق، <span dir="ltr">Inbox</span>، اتوماسیون و پیش‌بینی محلی در آن پیاده‌سازی شده‌اند. قابلیت‌های هوش مصنوعی محلی اختیاری هستند و خاموش کردن آن‌ها نباید هیچ جریان اصلی برنامه را مختل کند.

## انتشار نسخه برای استفاده

برای هر تغییر در شاخه اصلی یا Pull Request، GitHub Actions به‌صورت خودکار قالب‌بندی، تحلیل کد و تست‌ها را اجرا می‌کند.

برای ساخت نسخه قابل انتشار در GitHub:

1. مقدار `version` در <span dir="ltr"><code>pubspec.yaml</code></span> را به نسخه جدید تغییر دهید؛ برای مثال `1.1.0+2`.
2. تغییرات را commit و به شاخه اصلی push کنید.
3. یک tag با قالب `vMAJOR.MINOR.PATCH` بسازید؛ برای مثال `v1.1.0`.
4. tag را به GitHub push کنید:

   ```bash
   git tag v1.1.0
   git push origin v1.1.0
   ```

پس از push شدن tag، workflow انتشار نسخه را اجرا می‌کند، تست‌ها و تحلیل را دوباره انجام می‌دهد، APK اندروید را می‌سازد و آن را در GitHub Release همان tag قرار می‌دهد.

> در وضعیت فعلی، build اندروید با signing موجود پروژه ساخته می‌شود و برای تست و انتشار داخلی مناسب است. برای انتشار عمومی در Google Play یا توزیع تجاری، باید keystore اختصاصی ایجاد و مقادیر حساس آن در GitHub Actions Secrets تنظیم شود؛ کلید امضای خصوصی نباید در repository قرار بگیرد.
